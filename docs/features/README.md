## 📝 When to add documentation here:

Add documentation to this folder when you're documenting:
- New feature implementations
- Feature functionality and usage
- API endpoints for features
- Feature-specific workflows
- Data seeding and population
- Integration of third-party features
- Feature quick start guides
- Feature architecture and design

## 💡 Naming Convention:

Use UPPERCASE with underscores:
- `FEATURE_NAME_SYSTEM.md` - For comprehensive feature docs
- `FEATURE_NAME_QUICKSTART.md` - For quick start guides
- `FEATURE_NAME_INTEGRATION.md` - For integration guides
- `FEATURE_NAME_API.md` - For API documentation

## 📚 Documentation Template:

When documenting a new feature, include:
1. **Overview** - What the feature does
2. **Implementation** - How it's implemented
3. **Usage** - How to use it
4. **API Endpoints** - Available endpoints
5. **Examples** - Code examples
6. **Testing** - How to test the feature
